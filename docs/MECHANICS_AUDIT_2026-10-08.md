# Mechanics inventory: all 34 retained games

Audit date: 2026-10-08. This document supersedes broad “verified” or “calibrated” claims in the earlier fidelity audit wherever the two differ.

## Scope and evidence labels

This is a local, play-credit implementation. **Implemented** means the named behavior exists in code. **Corrected** means this pass changed a source-confirmed mismatch. **Local approximation** means an intentionally local table, probability, animation, cap, or implementation substitutes for the source. **Verified missing** identifies an observable feature not implemented. **Unverified** means the necessary primary evidence was not captured; it does not mean the feature is absent from the original. **Proprietary** means unavailable server/PAR/reel information. Passing tests is not a provider certification or proof of exact RTP.

Public provider rules and first-party operator help were checked against the engines, current route components, and tests. Provider versions and jurisdiction-specific feature purchases can differ. The audit does not claim that all mechanics of all versions have been reproduced. Original artwork is deliberately local; symbol-art aliases can differ while numerical pay classes match.

## Atomic purchase contract

Wanted `buyLineBonusRound(rng, profile, baseBet, bonus)` returns `purchaseCost`, `totalPayout`, `bonus` and the complete `spins` presentation sequence. Price is baseBet×80/200/400; the payout cap stays baseBet×12,500. The UI must validate fresh funds, acquire its synchronous round lock, debit the full price once, consume one nonce, calculate the complete feature, credit once and record that same full price before animation. Calculation failure refunds only an unsettled debit. Closing a menu does not purchase. Repeated confirm/spin, route departure, skip, and refresh must not create another debit or abandon part of the payout.

Each Wanted result can expose `triggeredBonus`, `reelMultipliers` and `wantedState` (`bonus`, `phase`, `stickyWilds`, `collectedWilds`, `collectedMultiplier`, `respinsRemaining`). Collect-phase entries are zero-paying prepared spins, not extra wagers. The UI labels remaining respins from `respinsRemaining`; Showdown receives exactly 3 spins. Natural base play chooses the actually triggered feature.

6. **Controls and variants:** parity of every advanced autobet condition, provider keyboard shortcut and operator-specific stake/currency limit was not established. Blackjack surrender/split variants and live Baccarat pair bets are kept distinct from the pinned core rules.
7. **Locally defined games:** Three Cups, Classic Slot, Scratch Card and Bingo retain visible local prize rules. Bingo does not implement multiplayer rooms, multiple-card purchasing or every possible pattern game. They are not replicas of a single named provider product.

All 34 routes have an inventory row, but this is not a claim that every observable detail of every original version is complete.
